# Review checklist

Work through the sections in order. Section A failing invalidates the rest. Mark each item ✅, ❌, or ➖ (not applicable). Every ❌ against a SHOULD rule needs an entry in the decision log (DEC-08).

## A · Decision (DECISIONS.md)
- [ ] A written purpose exists, and every element on screen serves it (DEC-01, DEC-03)
- [ ] One feeling is named, and colour, type and motion point at it (DEC-02)
- [ ] One hero is identifiable within two seconds of looking at the screen (DEC-04)
- [ ] Constraints and the accessibility target are recorded (DEC-05)
- [ ] Every broken convention has a recorded reason (DEC-06)

## B · Layout (ui/01)
- [ ] Nothing interactive or essential sits outside the safe area (LAY-01)
- [ ] Works on the smallest and largest size, both orientations, and the largest text size (LAY-03)
- [ ] Every gap comes from the spacing scale (LAY-05)
- [ ] Gaps between groups are at least 2× the gaps within groups (LAY-06)
- [ ] Margins match across screens (LAY-07)
- [ ] Alignment edges are few and deliberate; optical corrections are applied (LAY-09, LAY-10)

## C · Typography (ui/02)
- [ ] No text below the platform minimum (TYP-01)
- [ ] No light weights at body size (TYP-02)
- [ ] Layout holds at 200% text and with WCAG spacing overrides (TYP-03, TYP-05)
- [ ] Long-form text runs 45–90 characters per line (TYP-04)
- [ ] Only styles from the defined set are used (TYP-06)
- [ ] At most two typefaces (TYP-08)
- [ ] Kerning on, tracking adjusted by size, all caps tracked (TYP-09, TYP-10)
- [ ] Correct quotes, dashes, ellipses and minus signs; tabular figures in columns (TYP-11, TYP-12)

## D · Colour (ui/03)
- [ ] Text meets 4.5 : 1 (3 : 1 for large text) in light and dark modes (COL-01)
- [ ] Non-text UI and focus indicators meet 3 : 1 (COL-02)
- [ ] Body text reaches APCA Lc 75 (COL-03)
- [ ] No meaning carried by colour alone (COL-04)
- [ ] Each colour has one role; colours are referenced by role (COL-05, COL-06)
- [ ] Every custom colour has four variants (COL-07)
- [ ] Accent colour is used on one primary action per view (COL-09)

## E · Shape and materials (ui/04)
- [ ] Nested radii follow inner = outer − padding (SHP-01)
- [ ] Only radii from the closed set are used (SHP-02)
- [ ] Glass only in the control layer; never glass on glass (SHP-04, SHP-05)
- [ ] Clear glass only over media, with dimming over bright media (SHP-06)

## F · Motion (ui/05)
- [ ] Every animation carries information (MOT-01)
- [ ] Nothing communicated only through motion (MOT-02)
- [ ] Animations are interruptible and follow the gesture (MOT-03, MOT-04)
- [ ] Reduce Motion is honoured with fades and tightened springs (MOT-08)
- [ ] Nothing flashes more than 3 times per second (MOT-09)

## G · Interaction (ux/01)
- [ ] Targets meet the platform default; none below the minimum (INT-01, INT-02)
- [ ] 12 pt padding around bezeled controls, 24 pt around borderless ones (INT-03)
- [ ] Every gesture has a visible alternative (INT-06)
- [ ] Fully operable by keyboard and switch, with a visible focus indicator (INT-07, INT-10, ACC-04)

## H · Feedback (ux/02)
- [ ] Every input produces a visible response within 100 ms (FBK-01)
- [ ] Operations over 1 s show progress; over 10 s, an estimate and a cancel option (FBK-01, FBK-03)
- [ ] Empty, loading, error, offline and long-content states are designed (FBK-04)
- [ ] Undo is used where possible; confirmation only for irreversible destructive actions (FBK-05)
- [ ] Errors appear next to their cause, state the fix, and do not blame (FBK-07)

## I · Structure and words (ux/03, ux/04)
- [ ] Every screen shows location, destinations and the way back (NAV-03)
- [ ] No flow traps the person (NAV-04)
- [ ] Buttons are verbs; capitalisation is consistent; no "we" in errors (WRT-03, WRT-04, WRT-06)
- [ ] No concatenated strings; room left for translation (WRT-10)

## J · Access and trust (ux/05, ux/06)
- [ ] Every element has an accessible name, role and value; reading order matches visual order (ACC-01, ACC-02)
- [ ] Tested with the screen reader, largest text, Increase Contrast, Reduce Motion and Reduce Transparency (ACC-09)
- [ ] Permissions requested in context, with a reason (TRU-01)
- [ ] Generated output is previewed and confirmed before consequential actions (TRU-04)
- [ ] No dark patterns (TRU-05)
